## 阻塞点取证链（完整还原）

**症状**：裁决测试 `agent did not reach idle in time`——真回合从未走到 turn-stopping。

**逐层取证（全部本地 node_modules + 运行时探针实证）**：

1. **claim 不触发驱动**：`harness.claim(agent, 'next-turn', 1)` 后仅有 `agent/inbox/inserted` + `agent/inbox/claimed` 事件，status/pre-step/request 全零。testkit claim = `agent.inbox.claim(target, turn)` 转发（testkit lib/index.js L122），语义 = 准入（admit），**不 wake**。README L51 示例止于 claim，未展示唤醒步骤。
2. **wakeDriver 可驱动**：`agent.wakeDriver()`（ReactLoopAgent L854）后事件流活了：status(running) → pre-step → **error** → status。kick→turn→preStep 链走通。
3. **preStep 崩点**：`dsh-agent-loop/lib/index.js:920` `if (decision.kind === "reject")` TypeError reading 'kind'——**waterfall("agent/pre-step", payload, fallback) 返回 undefined**（await 后即炸，无中间帧）。
4. **链首探针实证**：`{ prepend: true }` 探针监听器进入并打印 `await next()` 返回 **undefined**；尾部探针**从未被调**——链在某个中间 hook 处断裂（该 hook 返回 undefined 且未调 next）。
5. **纯 cordis+dsh-scope 对照实验（T1-T3）全部正常**：无 carrier / carrier+fallback / carrier+root 监听器三种形态，fallback 与监听器行为全部符合 waterfall 语义 → **cordis 本身无罪**。
6. **carrier filter 无罪**：手动执行 carrier[Context.filter] 对 root/loopCtx/agent.ctx 三个 ctx 全部放行 true。
7. **hook 形态异常**：loopCtx 与根 ctx 的 events 服务实例不同（`!==`）但 `agent/pre-step` hooks 数量镜像（2→3 随探针累积同步变化），hook.callback 均为 reflect Proxy 包装（native code）；链上存在一个**同步 Function（非 async）hook**，最可疑为断裂点（被调后返回 undefined 跳过下游）。
8. **已排除**：gate 插件（未挂 pre-step，仅 tools/result / turn-stopping / disposed / inbox/claimed / system-prompt/assemble / fs-intent×2）；dsh-scope invariant（挂 internal/dispatch global）；dsh-invariants（纯注册表）；payload.agent 引用比较（payload 形状 `{agent: Agent, status}` 实证无误）。
