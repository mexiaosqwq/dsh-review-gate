## 4. 独立推演盲区（复核面 ④）

### ① noNewReviews 清零语义——**设计意图可辩护，非误伤；效果依赖会话形态（备忘）**

micro ack 清零 = 「连续 full+零发现」streak 语义的字面实现（合同 A2 原文）。形态推演：**burst 会话**（多文件/回合）micro 稀疏、full 结算连续出现 → 计数能积到 K，防护生效；**dribble 会话**（1 文件/回合）每回合 micro ack 清零 → 计数恒 0 → drift 升格永不降格。但 dribble 形态下 full 本来每 ~milestoneAtFiles（10）个文件才触发一次，疲劳压力成比例地低——防护靶向 burst 场景的 full 风暴恰是合理设计；且 README 行「连续 K 次 full 复审零新发现」已把重置语义写进文档字面。判定：无需动作；若晨间用户认为 dribble 也应积计数，那是合同变更（需用户拍板），不是缺陷修复。

### ② stop_loss 边缘场景可达性——**实证可达且非罕见，判据语义成立**

关键发现：decideReview 自带 `if (chain >= config.maxChain) return 'skip'` 守卫（state.ts，F1 diff 上下文可见）——链满后**新写不再武装复审**（gradeAndArm 得 skip → pendingReview null）→ 该写回合 turn-stopping 走 nothing-owed 分支 return 'skip' + chain 满 → 监听器落 stop_loss 行。即 stop_loss 行有**两条生产触发路径**：① handleTurnStopping 止损分支（pendingReview 已武装但放弃）；② decideReview 链满 skip + nothing-owed（新写根本未武装）。路径②意味着「链满期每个写回合落一条 stop_loss 行，直到 user claim 衰减」——行量比 worker 预估「每次止损一行」略高（路径②逐回合计），但仍温和有界。语义「回合有写但复审被放弃」对两条路径都成立——worker 偏差注记 2 的「可辩护」判断**验证为真**，无需更严判据。

### ③ 双源一致性（`?? 3` vs `Config default(3)`）——**今天一致，漂移面静默，候选 +1 行钉死**

两源相距 ~200 行（state.ts decideReview vs index.ts Config schema）。现有测试钉死了 `??` 回退路径（用例 1：noNewReviews=2 < 兜底 3 照升格），但**没有**交叉断言 Config default 值——若未来改 Config default 为 5，宿主行为变 5、回退路径仍 3、测试全绿 = 静默分叉。修法候选：gate.test.mjs +1 行 `assert.equal(gate.Config({}).noNewReviewsBeforeDemotion, 3)`（或抽共享常量）。可选，不阻塞。

### ④ `void appendReceipt` 失败静默——**可接受，且与既有 ceiling 一致**

追杀点：`void p` 只丢返回值、**不吞 rejection**——若 appendReceipt 内部无 catch，写失败会走 unhandledRejection（node ≥15 默认致命）。取证：appendReceipt（index.ts L83-91）内部 `try { mkdir + appendFile } catch {}` 全吞，附 ponytail 注释「audit failures are silent — an audit log must never interrupt a review」→ promise 恒 resolve，void 安全。止损审计行丢失的后果 = 可观测性缺口（非功能损伤），与 ack 行的既定静默 ceiling 完全同构——一致设计，接受。
