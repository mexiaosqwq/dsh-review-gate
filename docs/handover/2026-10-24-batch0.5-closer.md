## 2. 高风险数据流：tilde + 未跟踪新文件

在 `~/tmp` 下建真实临时 git 仓库（避免 `/tmp` 垫片），提交基线后创建未跟踪 `newfile.txt`；直接检查 git 输出形态：

```text
git -C <root> ls-files --others --exclude-standard -- <root>/newfile.txt
→ newfile.txt                    # root-relative，不是绝对路径

git -C <root> ls-files --others --exclude-standard -- <root>/sub/dir/new.ts
→ sub/dir/new.ts                 # 嵌套路径同理
```

调用当前 `lib/index.js` 的 `collectDiff`：

```text
ABS   = diff --git a/.../newfile.txt ... +new line
TILDE = diff --git a/.../newfile.txt ... +new line
equal = true
nested tilde = diff --git a/.../sub/dir/new.ts ... +nested new
mixed tilde (tracked.txt + newfile.txt) =
  diff a/tracked.txt ... +tracked change
  diff a/.../newfile.txt ... +new line
```

结论：`untrackedAmong` 收到绝对路径时，git 仍输出 **root 相对路径**；因此 `diffNewFile(joinPath(root, rel))` 收到的是正确绝对路径，未跟踪全增 diff 正常渲染。不存在“git 输出绝对路径 → `joinPath(root, abs)` 变成 `root/abs`”的失效。该组合未写入仓库测试（F1），但独立实测通过。

真实生产路径复核（cwd = home）：

```text
collectDiff(['~/dsh-review-gate/README.md'])
→ 675 chars，含「取证路径解析」行
collectDiff([abs path])
→ 675 chars；equal true
```

## 6. Findings

### F1 · minor | `test/gate.test.mjs:619-658`（新测试）；`test/gate.test.mjs:601-616`（既有 untracked 用例）

**事实**：新测试只创建并提交 `f.txt` 后修改它（tracked）；仓库内**未跟踪新文件**没有用 `~/` 路径进入测试；既有 untracked 用例只使用绝对路径。高风险分支 `untrackedAmong(root, resolved) → diffNewFile(joinPath(root, rel))` 的组合没有自动化断言。

**影响**：本次手工实测通过（见 §2），但未来若有人改动 `untrackedAmong` 输出/`joinPath`，现有测试不会红；这正是 lead 点名的高风险路径，回归护栏缺失。

**最小修法**：在 619-658 内（不新增测试数）追加一个仓库内未跟踪文件，例如 `brand-new.ts`，然后：

```js
const fresh = join(dir, 'brand-new.ts')
await writeFile(fresh, 'fresh line\n')
const tildeFresh = `~/${_relative(_homedir(), fresh)}`
const d = await collectDiff([tildeFresh])
assert.match(d, /new file mode/)
assert.match(d, /\+fresh line/)
```

可再补 mixed `collectDiff([tildeTracked, tildeFresh])` 断言两段并存；`~user` 字面不展开可用静态代码审查或单独小用例（当前实现已正确，测试未覆盖）。

### F3 · info | `README.md:174`

**事实**：新文案说相对路径“按宿主进程 cwd 解析……拿不到证据”，但实测 home cwd 下 `dsh-review-gate/README.md` 返回 **`''`**（0 chars），不是 `null`；`''` 被现有 `countChangedLines`/`shouldWaive` 视为零净变更、可豁免。相对路径仍是 §11.6 明确不修的已知缺口，代码未改变。

### F4 · info | `test/gate.test.mjs:639-650`

**事实**：新测试断言 `collectDiff(['~']) === null`，并在 `~/tmp` 下建 plain 目录断言 null，隐含假设 `$HOME` 自身不是 git 仓库。若用户 home 是 dotfiles repo，裸 `~` 会找到 home 的 `.git`，plain 目录也被 home 仓库覆盖，两个负例可能失败。

**影响**：测试在“home 是 git 仓库”的开发机上不可移植；当前 Termux home 不是仓库，本机绿。

**最小修法**：在负例前跳过 `existsSync(join(homedir(), '.git'))` 的环境，或用子进程临时 HOME 隔离；也可只用 `~/tmp` 内自有 repo 的正例，避免对 home 下结论。info 级，不阻断。
