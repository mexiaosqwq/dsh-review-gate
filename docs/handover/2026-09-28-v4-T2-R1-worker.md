## STOP 取证：maxChain 止损在真时序失效（lib 行为与断言不符）

**证据链**（探针 ~/tmp/forensics-t2r1.mjs 可复跑）：

1. 实测时间线：STEER#1 → TS#1 → STEER#2 → TS#2 → STEER#3 → TS#3（每回合关闭必 steer，3 次后脚本按预算耗尽止住，否则无界）
2. **3 条 steer 消息内容完全相同**——同一条 pendingReview 的 driver 消息逐回合重放（无 ack、无结算）
3. receipts 为空（无 ack 场景，符合预期）
4. **根因（lib 源码定位）**：`src/index.ts` L468-471 的 `agent/inbox/claimed` 衰减 handler 不区分「用户新回合消息」与「driver steer 注入消息的续步 claim」——每次 steer 后 driver 的 preStep claim next-step 触发 claimed 事件 → `chain -= 1`，恰好抵消 `handleTurnStopping` 里的 `chain += 1`（L348）。chain 恒为 0 → `chain >= maxChain` 守卫（L342-346）永不触发。
5. **设计意图 vs 真实行为**：L341 注释「Stop-loss: an unacknowledged model cannot pin the loop forever」——真时序实证无 ack 模型确实可以 pin 住循环（每回合一条重放 driver 消息，永不结算）。fakeCtx 测试从未覆盖此形态（claim 由测试手动调，只有 user-only 场景；gate.test.mjs 的 chain 测试是纯函数级的，不经过 claimed 事件）。

**为什么不是测试假设错误**：断言 `1 <= steered <= 2` 来自计划（合同层，maxChain=2 是 v3.3 用户拍板的止损契约）；lib 真实行为 3 > 2 且机制上无界。属 Global Constraints 的「测试暴露 lib 行为与断言不符 → STOP，不修 lib」。
