## 3. 复核重点 ①：source 门控边界——**worker 一项主张证伪**

**主张原文（T2-lib 报告残留风险节）**：「当前唯一系统注入方就是 gate（grep 实证）」。

**独立 grep 裁定：FALSE。** DSH 运行时至少有三种非 user、非 gate 的 source kind 走 claimed 车道：

| 注入方 | source.kind | 场景 | 证据（DSH checkout node_modules，lib 构建） |
|---|---|---|---|
| dsh-cordis-host-runner | `cordis-host-runner` | 插件运行失败/渲染失败/host handler 失败/守卫拒绝 → `agent.steer(createUserMessage({…, source: { kind: "cordis-host-runner" }}))` | lib/index.js L2350/L2359/L2372/L2385 |
| dsh-experimental-agent-team | `team-message` | 团队信箱投递到 root agent → `root.steer(input)` | lib/types/mailbox.js L208-218 |
| dsh-subagent | `subagent-settled`（及 agentMessageSource 同胞消息 kind） | 后台子代理结算通知 → parent inbox | lib/index.js L647-652 区域 |

**但这不动摇修复本体**，影响评估：

1. **非新增风险**：v3.3 对所有 claim 无差别衰减（含 gate 自产重放=bug 本体）；denylist 只把 gate 自产消息排除，其他 kind 的衰减是**既有行为的保留**，严格收窄非放宽。
2. **无界重放不会经这些车道复活**：无界 bug 的成立条件是「按回合重放同一消息」（gate 每回合 turn-stopping 必 re-steer driver 消息）。cordis-host-runner 只在插件失败时发（非每回合）、team/subagent 消息是事件型一次性——没有任何系统注入方按回合重放。
3. **失败方向偏安全**：系统 kind 多衰减 → chain 提前降 → gate 提前恢复 steer = 多复审（烦扰方向），不是保护丢失方向。

**语义层补充论证（denylist 并非次优解）**：注释字面（"A newly claimed user message"）支持 allowlist，但 maxChain 的止损意图（L338 注释 "an unacknowledged model cannot pin the loop forever"）防的是**gate 自己的重放 pin 住循环**——任何新鲜非 gate 输入（team 消息/结算通知/用户回复）都给了模型新上下文，pin 压力释放合理。denylist 与止损意图对齐，allowlist 与注释字面对齐，两者均有理据。

### 替代方案对比结论（lead 指定评估项，不改码）

| 维度 | denylist（现修复：kind==='review-gate' 跳过） | allowlist（仅 kind==='user' 衰减） |
|---|---|---|
| 注释字面语义 | 次贴 | 贴 |
| 止损意图（防 gate 自 pin） | 贴（最小 delta 直击 bug 本体） | 贴（且额外免疫未知重放型注入方） |
| 对 v3.3 行为的增量 | 最小（只排除一种 kind） | 大（额外改变 cordis-host-runner/team/subagent 三种 kind 的既有衰减行为，超本 bug 爆炸半径） |
| 依赖假设 | 无（可选链防缺形） | 依赖「用户消息恒带 kind='user'」——真实 client 已实证恒带（api-session-controller L856-860 `source = { kind: "user", rpcId, … }`），但一旦某路径漏 source → 停止损后 gate 在写回合连发场景**永久哑火**（chain 不衰减、L353 write-free 重置不触发）= 保护丢失方向 |
| 测试面代价 | 零（fakeCtx claimed 测试 message:{} 原样绿，实测 63/63） | fakeCtx claimed 测试会红（message:{} 无 source，undefined ≠ 'user' 不衰减 → 2!==3），需同步改 +1 行 |

**结论：维持 denylist。** allowlist 列为候选精化（仅当未来实证「系统 kind 衰减实际造成过度 steer」再议）；若采，代价 = src 1 行 + fakeCtx 测试 1 行。

## 4. 复核重点 ④：独立推演盲区（Task 3 依赖面 + 未来形态）

1. **turn 值未来变化**：source 门控不读 `payload.turn`，构造上免疫——优于已被证伪的 turn 门控（其死因正是时序依赖：state 诞生晚于首个 claim，基线必丢）。worker SEQ 铁证的时序盲区在新方案下不存在对应面。
2. **多消息续步**：`claim()` 逐条 emit（agent-loop lib/index.js L100-108：for 循环每条消息发一次 `agent/inbox/claimed`）→ 一个 claim 批含 N 条非 gate 消息 = N 次衰减。有界（受批大小约束）、非正确性洞；衰减方向是多复审（安全方向）。记录即可，不阻塞。
3. **ack 场景（Task 3 依赖）**：双路径安全——①计划 Task 3 的重放消息是 `userMessage(DRIVER_HINT)`（kind='user'）→ claim 衰减，但 ack 结算已 chain=0，衰减被 `chain > 0` 守卫挡住 = no-op，`steered === 0` 断言成立；②真实 client 重放无论保留原 source（review-gate → skip）还是重包为 user（衰减但 chain=0）都收敛。Task 3 不依赖 chain 值，只断言零拦截——本车道修复不构成 Task 3 风险。
4. **steer 通路契约**：`steer(input) → send(input, 'next-step', true) → inbox.splice(…, [message])` 原样 append（agent-loop L809-811 + send L799-804），source 保留；`claim()` emit 的 payload 形状 `{ message, turn }` 与 handler 可选链读取匹配——静态（源码）+ 动态（realloop 绿：若 source 未保留则重放 claim 会衰减、steered 会回到 3+ 红）双证。
5. **未来回归监测点**：修复的正确性耦合「buildDriverMessage 的 source.kind 在 inbox 往返中不被改写」这一宿主行为。若未来宿主对 steer 消息重贴 source（如统一盖 'driver' 章），bug 无声复发——但 realloop 的 `<= 2` 断言会红（steered 回到 3+），车道已埋好回归哨兵。
