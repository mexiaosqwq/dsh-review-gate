## 7. 残留风险

- **`~user` 形式不支持**：只展开裸 `~` 与 `~/`，`~someone/…` 原样传给 git（与修复前一致）。当前无此需求；若要支持需 `os.userInfo` 解析，属加料，未做。
- **相对路径仍按宿主 cwd**：这是刻意保留的既有契约（README 已写明）；会话 workspace ≠ 宿主 cwd 时相对路径仍拿不到证据——本次不改变，因为以「会话 workspace」为基准需要宿主侧传入 scope，属另一个接口级改动。
- **混合数组的 root 探测**：root 仍由**首个**路径（归一化后）向上找 `.git`；若首个路径不在仓库内、后续路径在仓库内，取证仍会 `null`——既有行为，未在本单扩展（跨仓库/多根场景）。
- **`~\`（Windows 反斜杠）不展开**：本机 Termux/Linux 无此形态；若未来上 Windows 需补 `~\\` 分支。
- **真机未验**：host 半区改动需重启 profile 才在用户进程生效（team 内单测跑 `lib/` 不受影响）。

### 7.1 小修 B0.5-F4（2026-10-24 lead 裁定）

`test/gate.test.mjs` 的裸 `~` 断言由 `assert.equal(..., null)` 换成环境无关形式：

```js
assert.deepEqual(
  await collectDiff(['~']),
  await collectDiff([_homedir()]),
  'bare ~ is expanded to home before resolution (same evidence as the absolute path)',
)
```

理由：旧写法隐含「$HOME 不是 git 仓库」的环境假设（换机器/换 HOME 即失效）；新写法只断言「`~` 与 `homedir()` 同解」，与宿主环境无关。判别力保留——旧码对 `~` 会从 `.` 向上取进程 cwd 的仓库（`''`/假证据），与 `homedir()` 的 `null` 不等即红；主证据仍由 `~/<file>` 的等价断言承担。

验证：`node --test --test-name-pattern '~/ paths' test/gate.test.mjs` → 1/1 通过；`npm test` → **100/100**（只改测试，`lib/` 未重建）。
